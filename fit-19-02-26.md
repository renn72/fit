## Summary
The consolidation eliminates the dual-table pattern in favor of a single-table design with discriminating boolean flags. This simplifies queries, reduces join complexity, and makes the data model more intuitive while maintaining the ability to track base item override overrides.

Route refactoring provides cleaner, shorter URLs that are more user-friendly and easier to share. The `/admin/s` prefix was unnecessarily verbose.

New dictator routes provide system administrators with comprehensive views of all users and organisations, enabling better oversight and management of the platform.

### SuperSet Support for Exercises
Added superset functionality to allow grouping exercises together:

**Schema Changes:**
- `packages/db/src/schema/exercise.ts`:
  - Added `isSuperSet: boolean` column to exercise table (defaults to false, notNull)
  - Added index `exercise_isSuperSet_idx` for filtering supersets
  - Created new `superSetToExercise` junction table:
    - `id`: UUID primary key
    - `superSetId`: references exercise.id (cascade delete)
    - `exerciseId`: references exercise.id (cascade delete)
    - `order`: integer for maintaining exercise order within superset
    - `createdAt`: timestamp
    - Indexes: `superset_superSetId_idx`, `superset_exerciseId_idx`
    - Unique constraint: `superset_unique_idx` on (superSetId, exerciseId)

**Relations Updates:**
- `packages/db/src/relations.ts`:
  - Added `superSetExercises` relation on exercise (links to superSetToExercise as parent)
  - Added `parentSuperSets` relation on exercise (links to superSetToExercise as child)
  - Added `superSet` relation on superSetToExercise (links back to parent exercise)
  - Added `exercise` relation on superSetToExercise (links back to child exercise)

**API Changes:**
- `packages/api/src/schemas/exercise.ts`:
  - Added `SuperSetAddExerciseInput` schema (superSetId, exerciseId, order)
  - Added `SuperSetRemoveExerciseInput` schema (superSetId, exerciseId)
  - Added `SuperSetGetExercisesInput` schema (superSetId)

- `packages/api/src/routers/exercise.ts`:
  - Added `addToSuperSet` procedure (POST /exercise/superset/add):
    - Validates that superSetId points to an exercise with isSuperSet=true
    - Validates that exerciseId exists
    - Creates link in superSetToExercise table
    - Requires itemUpdater or dictator permissions
  
  - Added `removeFromSuperSet` procedure (DELETE /exercise/superset/remove):
    - Removes exercise from superset by deleting junction record
    - Requires itemUpdater or dictator permissions
  
  - Added `getSuperSetExercises` procedure (GET /exercise/superset/:superSetId):
    - Returns all exercises in a superset with full details
    - Includes movement information
    - Ordered by the `order` field

**Data Flow:**
```
Exercise (isSuperSet=true) 
  → superSetToExercise (junction)
    → Exercise (child exercises in superset)
```

**Usage Pattern:**
1. Create an exercise with `isSuperSet: true` to serve as the superset container
2. Use `addToSuperSet` to link child exercises to the superset
3. Use `getSuperSetExercises` to retrieve all exercises in the superset
4. Use `removeFromSuperSet` to remove exercises from the superset
5. Delete the superset exercise to cascade delete all junction records

### Session Management System
Added complete session management to organize exercises and supersets into workout sessions:

**Schema Changes:**
- `packages/db/src/schema/session.ts` - New file with three tables:

**session table:**
- `id`: UUID primary key
- `name`: text (required) - session name
- `description`: text (optional) - session description
- `category`: text (optional) - session category
- `creatorId`: references user.id (set null on delete)
- `organisationId`: references organisation.id (cascade delete)
- `createdAt`: timestamp
- `updatedAt`: timestamp with auto-update
- Indexes: `session_creatorId_idx`, `session_organisationId_idx`

**sessionToExercise junction table:**
- `id`: UUID primary key
- `sessionId`: references session.id (cascade delete)
- `exerciseId`: references exercise.id (cascade delete)
- `index`: integer (required) - maintains exercise order in session
- `createdAt`: timestamp
- Indexes: `session_exercise_sessionId_idx`, `session_exercise_exerciseId_idx`
- Unique constraint: `session_exercise_unique_idx` on (sessionId, exerciseId)

**sessionToSuperSet junction table:**
- `id`: UUID primary key
- `sessionId`: references session.id (cascade delete)
- `superSetId`: references exercise.id (cascade delete) - must be exercise with isSuperSet=true
- `index`: integer (required) - maintains superset order in session
- `createdAt`: timestamp
- Indexes: `session_superset_sessionId_idx`, `session_superset_supersetId_idx`
- Unique constraint: `session_superset_unique_idx` on (sessionId, superSetId)

**Relations Updates:**
- `packages/db/src/relations.ts`:
  - Imported session schema
  - Added `sessions` relation on user (sessions created by user)
  - Added `sessions` relation on organisation (sessions in organisation)
  - Added `exercises` relation on session (linked via sessionToExercise)
  - Added `superSets` relation on session (linked via sessionToSuperSet)
  - Added `session` and `exercise` relations on sessionToExercise
  - Added `session` and `superSet` relations on sessionToSuperSet

**API Router:**
- `packages/api/src/routers/session.ts` - New router with full CRUD:
  - `getAll` (GET /session/all) - Dictator only, get all sessions across orgs
  - `getAllOrg` (GET /session/org) - Get sessions for an organisation
  - `get` (GET /session/:id) - Get session with all exercises and supersets (deeply nested)
  - `create` (POST /session) - Create new session
  - `update` (PATCH /session) - Update session details
  - `delete` (DELETE /session/:id) - Delete session
  - `addExercise` (POST /session/exercise/add) - Add exercise to session with index
  - `removeExercise` (DELETE /session/exercise/remove) - Remove exercise from session
  - `addSuperSet` (POST /session/superset/add) - Add superset to session with index
  - `removeSuperSet` (DELETE /session/superset/remove) - Remove superset from session

**API Schemas:**
- `packages/api/src/schemas/session.ts` - New file with Zod schemas:
  - `SessionGetAllOrgInput`, `SessionGetInput`, `SessionCreateInput`, `SessionUpdateInput`, `SessionDeleteInput`
  - `SessionAddExerciseInput`, `SessionRemoveExerciseInput` (with index field)
  - `SessionAddSuperSetInput`, `SessionRemoveSuperSetInput` (with index field)

**Router Registration:**
- `packages/api/src/routers/index.ts`: Added sessionRouter to appRouter

**Data Flow:**
```
Session
  → sessionToExercise (junction with index)
    → Exercise (individual exercises in session)
  → sessionToSuperSet (junction with index)
    → Exercise (isSuperSet=true, contains nested exercises via superSetToExercise)
```

**Key Features:**
- Sessions can contain both individual exercises and supersets
- Index field maintains order of items within a session
- Deep loading: get session → supersets → exercises in each superset
- Permission checks: itemUpdater or dictator for modifications
- Organisation-scoped: sessions belong to organisations
