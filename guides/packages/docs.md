# docs

## Purpose

- Stores loose technical reference notes for developers and agents.
- Holds ad hoc implementation notes that do not belong in runtime packages.

## Key Paths

- `packages/docs`

## Current Shape

- Lightweight reference folder for technical notes such as ORM or form-library guidance.
- Not a runtime dependency boundary and not a deployable app.

## Change Rules

- Keep notes practical and close to real repo decisions.
- Do not let this folder drift into stale architecture fiction; prefer repo-root docs for active source-of-truth summaries.
- When a note becomes critical operating context, promote or link it from the relevant top-level doc.
