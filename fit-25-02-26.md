## Tasks

### User Menu Assignment System
- **Created 4 new database tables** (`packages/db/src/schema/user-menu.ts`):
  - `userMenu` - Main assignment linking users to menu templates with date ranges, isActive flag, and total macros
  - `userMeal` - Meal level aggregation with target/actual macros (calories, protein, fat, carbs) and completion tracking
  - `userRecipe` - Standalone recipe copies (NOT linked to recipe table) with full recipe data including instructions, prep/cook times, servings, and calculated macros
  - `userIngredient` - Ingredient assignments with serve sizes, alternative ingredients, and completion tracking
  
- **Dual-Index Pattern**: Used mealIndex + recipeIndex throughout for complex meal planning without nested arrays
  
- **Relations updates** (`packages/db/src/relations.ts`):
  - Added userMenu import and schema spread
  - User → userMenus (one-to-many)
  - userMenu → meals, recipes, ingredients (one-to-many)
  - userMeal → userMenu
  - userRecipe → userMenu, ingredients (via separate query)
  - userIngredient → userMenu, userRecipe, ingredient, altIngredient
  - Ingredient → userIngredients, altUserIngredients

- **API Router** (`packages/api/src/routers/user-menu.ts`):
  - Full CRUD for userMenu: getByUser, get, create, update, delete
  - User Meal endpoints: createMeal, updateMeal, deleteMeal
  - User Recipe endpoints: createRecipe, updateRecipe, markRecipeCompleted, deleteRecipe
  - User Ingredient endpoints: createIngredient, updateIngredient, swapIngredient, markIngredientCompleted, deleteIngredient
  - All endpoints include permission checks (users can only modify their own menus, dictator override for admins)
  - Deep loading support: userMenu → meals → recipes → ingredients

- **Schemas** (`packages/api/src/schemas/user-menu.ts`):
  - Input validation for all 4 entities
  - Date handling for startDate/endDate
  - Macro calculation fields (calories, protein, fat, carbohydrate)
  - Completion tracking (isCompleted, completedAt)

- **Router registration** (`packages/api/src/routers/index.ts`):
  - Added userMenuRouter import and registration under `userMenu` key

### User Menu Creation UI
- **Sidebar update** (`apps/web/src/components/admin-sidebar/app-sidebar.tsx`):
  - Added "User" section at top of navigation (first item in navMain)
  - Contains "Create Menu" link pointing to `/$orgSlug/user-menu-create`
  - Uses UserIcon from Phosphor Icons
  - Positioned above Nutrition and Fitness sections

- **Create Menu page** (`apps/web/src/routes/$orgSlug/user-menu-create.tsx`):
  - Two-step workflow: template selection → configuration form
  - **Step 1 - Template Selection**:
    - Grid layout showing all available menu templates
    - Each card displays: template name, recipe count, description
    - Click to select and proceed
    - Shows message if no templates available
  - **Step 2 - Configuration Form**:
    - Fields: Menu Name (required), Description (optional), Start Date, End Date
    - Auto-fills name and description from selected template
    - Template preview showing recipe count
    - Submit creates full user menu structure with nested meals and recipes
  - **User Selection Check**:
    - Validates `?user=userId` in URL search params
    - Shows "No User Selected" card if no user selected
    - Prompts user to select from sidebar first

- **URL-based User Selection**:
  - Uses TanStack Router search params with `retainSearchParams` middleware
  - Persists user selection across all navigation
  - Sidebar NavUser component updates URL on selection change
  - Default falls back to current logged-in user

## Summary
Major feature completion: Complete user menu assignment system allowing assignment of menu templates to users with full tracking capabilities. The system follows the dual-index pattern for complex meal planning, supports hierarchical nutrition tracking (Menu → Meals → Recipes → Ingredients), includes completion tracking at every level, ingredient swapping, and macro calculations. The UI provides a seamless two-step creation workflow with template selection and configuration, all scoped to the selected user via URL parameters.
